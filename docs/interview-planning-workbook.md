## 10 / AI architecture and capacity

### Do you need multiple AIs?

You need separate capabilities, not a separate reasoning model for every student or station. One text-model service can handle probes and feedback in separate requests with different instructions. Each request contains that learner's relevant context. Speech recognition turns audio into text; text-to-speech turns a generated question into audio. These may be separate services.

**Suggested flow:** recorded question → candidate speech → transcription → pause and confirmation → save answer → optional text-generated probe → TTS → final feedback after the station.

### Current code and proposed extensions

| Capability | Current project / next decision |
| --- | --- |
| Probe text + feedback | Gemini 3.5 Flash-Lite defaults, separately configurable. Calls require existing server configuration. |
| Eligible probing stations | Owner-controlled allowlist is empty at this review. Select station IDs before enabling probes. |
| Recognition and voice | Browser Web Speech APIs. Chirp and ElevenLabs are recommendations, not installed services. |
| Data-station assessment | Currently title + answers; add approved stimulus facts and station-specific rubric. |
| UCAT reports | Separate existing Claude integration; do not count it as interview voice capacity. |

### Capacity planning

**Concurrent live stations:** ____   **Mean station length:** ____ minutes.

**Mean probes per station:** ____   **Feedback requests per station:** ____.

Average text requests/minute ≈ concurrent stations × (probes + feedback requests) ÷ station minutes. For example, 100 simultaneous eight-minute stations with two probes and one report average 37.5 requests/minute; synchronised completions can create much larger bursts.

Google applies quotas per project, including requests/minute, input tokens/minute and requests/day; extra keys do not multiply them. Read your actual account limits. [Gemini rate limits](https://ai.google.dev/gemini-api/docs/rate-limits)

**Build priorities:** bound probe count and length; reuse saved outputs; apply timeouts; queue final feedback when busy; retain a fixed-question fallback; measure errors and actual usage. Add another provider when measured reliability or quality requires it. Test before promising a concurrency level.

**Provider suitability:** the present Gemini Developer API terms exclude clients directed at or likely used by under-18s and require paid services for UK/EEA/Swiss users. Many medicine applicants are under 18: resolve a suitable provider/product agreement before that launch. Paid billing alone does not remove the age restriction. [Gemini terms](https://ai.google.dev/gemini-api/terms)

### Formulas

- Text request cost = (input tokens × input rate + billable output tokens × output rate) ÷ 1,000,000. Include billable reasoning tokens.
- Probe cost = number of probes × (probe text request cost + probe TTS cost).
- Station cost = report cost + probe cost + transcription + variable delivery/storage.
- Monthly variable cost = completed-station cost + abandoned/failed/retried usage. Add the reserve once, then fixed monthly costs.
- For a character allowance: monthly TTS = max(0, total billable characters − allowance) × rate. For a subscription: use the plan minimum plus overages; do not count the same included usage twice.
- GBP budget = USD cost × chosen GBP-per-USD assumption. Add applicable taxes separately.

## 12 / Worked cost example

**Illustration, not a quote or measured bill.** This models future paid operation. It does not change the existing personal free-tier setup. It deliberately ignores free allowances to avoid building a business case on them.

### Assumptions per completed station

- One report: 3,000 input tokens and 1,000 billable output tokens.
- Two probes: each 2,000 input tokens and 100 billable output tokens.
- Each probe contains 180 newly synthesised characters; fixed prompts are prerecorded.
- Text rates: Gemini 3.5 Flash-Lite standard $0.30 input / $2.50 output per million tokens. [Google text pricing](https://ai.google.dev/gemini-api/docs/pricing)
- TTS: Chirp 3 HD $30 per million characters before allowances. [Google TTS pricing](https://cloud.google.com/text-to-speech/pricing)
- Reserve 20%; conversion assumption $1 = £0.75. This is not a live exchange rate.

| Component | Calculation | USD |
| --- | --- | --- |
| Final text feedback | (3,000 × 0.30 + 1,000 × 2.50) ÷ 1,000,000 | $0.00340 |
| Two text probes | 2 × (2,000 × 0.30 + 100 × 2.50) ÷ 1,000,000 | $0.00170 |
| New probe speech | 360 characters × 30 ÷ 1,000,000 | $0.01080 |
| Subtotal | Feedback + probes + speech | $0.01590 |
| With 20% reserve | $0.01590 × 1.20 | $0.01908 |
| In GBP at assumed rate | $0.01908 × 0.75 | £0.01431 |

That is **about 1.43p per station for these components only**. At 20 stations/month it is about £0.29 per learner; at 60, about £0.86. At 1,000 learners doing 20 stations each, these components total about £286/month. Actual allowances and provider changes alter the bill.

**Excluded:** paid transcription, hosting, file delivery/storage, payment fees, taxes, failed/abandoned use beyond the reserve, support, content production and customer acquisition. Browser recognition has no paid transcription integration in the current app, but a dependable cross-device service needs its own budget.

**Sensitivity example:** if you budget an illustrative $0.01/minute for six minutes of transcription, add $0.06 per station before the reserve, or 5.4p after the same reserve and exchange assumption. Combined total becomes about 6.83p. The $0.01 rate is a placeholder to replace with a chosen provider quote.
