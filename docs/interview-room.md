# AI interview room

Open **AI Interviews → Build your interview**, or `/medicforest/interview/ai-interviews?setup=1`. Existing university, station and saved-attempt links use the same experience. The site's existing preview-access gate still applies.

Speech-to-text, text-to-speech and current cost options are summarised in [Interview speech options](interview-speech-options.md).

## Experience

- **Lobby:** choose a free station, a custom circuit, or university practice timings. University formats pre-select the published station count. Published data/numeracy formats include data practice; otherwise unpublished slots use a deterministic balanced selection. Ethics and current-issues topics have quantity steppers for distinct repeated stations. The summary includes preparation, station time and breaks. Scored practice starts only after joining.
- **Devices:** camera is off by default. Turning it on requests video only and displays a muted, mirrored self-view. The optional eight-second microphone test measures real input volume and releases its audio stream afterwards. Entering a new, resumed or preview interview automatically requests browser microphone access, including during reading time. The browser may remember a previous Allow or Block decision. The permission-check stream is released immediately; approved listening starts after the interviewer finishes speaking. Start mic is available for an explicit retry. Blocked or unavailable microphones leave typed answers available, and Start mic retries access. Read-aloud has three speaking paces and a test phrase.
- **Interview:** the active workspace fills the viewport, including navigation, notices and the room header. The call stage has blue and teal participant tiles with large circular avatars, subtle wave details and a pill-shaped bar of round microphone, camera and finish controls. Each control has an accessible name and a hover tooltip. The question appears in the transcript panel, with no duplicate question card above the participants. The narrower navigation sidebar, transcript and Notes scroll internally; question navigation and call controls stay visible. Small screens keep a compact participant strip above the transcript, with controls in a bottom row; short screens prioritise the answer editor. Voice and focus controls remain in the header. Escape closes the finish dialog before leaving focus view. Existing server timers, draft recovery, autosave and scoring are retained.
- **Follow-ups:** confirming an answer of at least 20 words saves it and asks one deeper question automatically. All current interview station topics are owner-enabled; each original prompt permits one follow-up and the server caps an attempt at three. The server inserts it into the saved station, and its answer is included in feedback and reports. Typed drafts are matched by question text so inserting a prompt cannot shift answers; stale autosaves preserve saved answers to prompts they have not seen. Preview never calls Gemini. When free quota is unavailable, a clearly labelled built-in practice prompt is used. Generated probes use optional server-side Chirp speech with a browser-voice fallback. See [AI and Chirp setup](interview-ai-setup.md).
- **Station review:** finishing or reaching the timer limit saves the transcript and opens its review, including short or empty attempts. The transcript, existing station answer framework and markscheme remain available without AI. Approximate talking speed appears only here as a side note and never affects the score. Feedback is generated only after an explicit request; its existing 20-word minimum still applies. Camera, accent, movement and eye contact are not assessed. A retry creates a new attempt, preserving the previous transcript in Saved Interviews.
- **Preview:** an explicitly labelled, in-memory walkthrough with sample feedback. It never creates, saves or grades an account attempt, and can skip reading time. Finishing opens the transcript and guide; illustrative sample feedback is available only when selected.

## Circuit selection

The session POST accepts an optional `stationSlug` and numeric `stationCount` (1–20 for customised circuits). Continuation always checks the owner's previous finished station, its persisted station count, and the existing break. An ungraded review or unsuccessful optional feedback does not prevent continuing. Premium requirements and practice allowances remain enforced on the server. Existing calls without these fields retain the original presets.

The remaining topic plan is kept in browser storage under the returned circuit ID. First joins send an explicit new circuit ID; if the database resumes a different active attempt, its existing plan is restored instead of being overwritten. If the plan is unavailable on another device, the review screen offers a topic chooser to continue the same circuit one station at a time. No database migration is required.

Saved Interviews supports station or university text search, a university filter, and feedback-status filters. Ended attempts open the same review; only an unexpired active attempt resumes the call. The compact review uses the question bank's shared `InterviewMarkScheme` component: General, Start, Middle and End, with collapsible sections, tickable points, coverage progress and the existing rubric PDF. Self-marking ticks are local to the displayed review and reset on retry. New AI feedback and transcript downloads use Strengths, Weaknesses and Fixes. Legacy improvements appear under Fixes; old reports without weaknesses say so rather than inventing them. Feedback remains JSON in the existing column; no SQL change is needed.

## Saved review lifecycle

`PATCH /api/interviews/session` accepts `finish: true` alongside the final answers and metrics. It saves and locks the snapshot in one conditional update, sets the submission and finish timestamps, and does not invoke AI. Once the existing 30-second transport grace has elapsed, finishing submits the last account snapshot and returns `usedSavedAnswers: true`; late text cannot extend practice time. Repeated finish requests preserve the locked transcript and timestamps. A conflicting autosave returns 409 so the client can reconcile before retrying.

The existing database status constraint and grading RPC remain unchanged: a finished, ungraded row uses `status = failed` with `last_error = awaiting_feedback`. `toInterviewAttempt` presents that combination as `submitted` to the application. This is a saved review, not a provider error. The first optional feedback claim can use that existing retryable row, and later grading preserves its original `completed_at` so the circuit break does not restart. Dashboard SQL continues to distinguish completed scored attempts from ungraded saved practice. The existing interview dashboard migration supplies `answer_submitted_at`; no additional migration is required.

A station retry reserves a fresh circuit ID and one station. University retries retain the university slug and its practice timings. Existing station-start allowances continue to apply; the original attempt is never deleted or reused as the retry.

## Data and placeholders

Device checks do not record or upload media. Camera tracks and calibration audio tracks are released when stopped, when submitting or leaving, and on unmount. Native microphone prompts cannot be dismissed by the app; a grant arriving after cancellation or unmount releases all tracks and cannot start speech. Pending prompts are reused across React effect replay. The browser's speech-recognition service may process spoken audio; Forest persists text transcripts only. Notes stay on the current call screen and are neither saved nor marked. In preview, feedback is illustrative regardless of the entered answer.

## Verification

### Speech and answer review

Question-bank recording stays available after Finish & Review until the user leaves or retries the question. The saved-response prop update must not discard the MediaRecorder's pending final blob. Review uses one transcript; playback highlights an estimated word within each timed recognition chunk. If typed text or edits no longer match that timeline, show the complete answer without claiming word alignment. Audio is local to the current screen and is not uploaded or restored with saved text.

Both speech flows preserve recognised slang and repetitions, wrap audible fillers as `[uhhh]` or `[um]`, and normalise legacy pause notation to `[3s pause]`. Only speech-boundary events with a preceding committed transcript can place a gap marker. Gaps shorter than three seconds, opening/trailing silence, recognition latency, and deliberate microphone breaks do not create markers. Browsers may omit fillers or speech-boundary events; missing evidence is never reconstructed from result latency.

Delivery coaching below the question-bank End section uses approximate words in the latest seven-second window ending in speech: under 13 is slow, 13–21 medium, above 21 fast. A complete seven-second span is required. Confidence warnings need at least 12 words with nonzero confidence and at least 35% below 0.65. Repeated-pause/sound coaching appears only for three long gaps, or at least three fillers/repetitions in 20+ words with an 8% rate. These are configurable coaching heuristics, not clinical assessments or scoring inputs.

`scripts/test-interview-speech.mjs` covers marker formatting, natural gaps, delayed recognition, pace thresholds and conditional coaching. Browser verification with a synthetic microphone confirmed final audio playback, a single transcript, replay highlighting, and animated/inert markscheme collapse. The AI room was checked at desktop and mobile widths for overflow, keyboard navigation and answer preservation.

`npm run test:interviews:room` exercises the session route with substituted account/database services, validates scoring, and checks that queued read-aloud cancels on Voice off, superseding requests and unmount. Microphone regressions cover entry during reading time, avoiding prompts in the lobby or feedback, permission success and denial/retry, late grants, effect replay, and unavailable APIs. It does not require credentials or call an AI provider.

`scripts/test-interview-review.mjs` covers finishing without AI, short/empty answers, idempotent locked snapshots, expired-answer recovery, concurrent saves, ownership and validation, ungraded circuit continuation, university retry settings, and keeping the original finish time through optional feedback success or failure.

Browser checks should cover station inclusion/exclusion, zero-selection validation, camera permissions, microphone test completion, typed-answer recovery, mobile overflow, question navigation, preview isolation, sample feedback, and next-station selection. Real provider speech recognition and AI grading depend on browser support and account/provider configuration.


Both speech flows use the same normalization, speech-boundary tracker and local microphone activity monitor. The monitor supplements missing native speech boundaries; recognition events remain the fallback when Web Audio or microphone access is unavailable. Silence markers require a 3-second gap between speech boundaries and committed preceding words. Opening silence, deliberate microphone breaks, and recognition/network delays do not create markers. Gaps with unresolved interim text are omitted rather than placed before the wrong words. Microphone energy is approximate and background noise can affect detection. Monitor tracks and AudioContext are released on stop, errors, unmount, and late permission grants.

The AI room uses the same delivery coaching as question practice. The transcript-count summary panel has been removed from both the room and review. Browser recognition may omit fillers and repetitions before returning text; these cannot be reconstructed reliably. Counts are not a clinical stutter assessment and do not affect scoring. Tests cover native boundary fallback, delayed results, local activity, brief energy dips, duplicate boundaries and late microphone cleanup.


### Sequential station conversation

New stations have no reading countdown. Join requests browser microphone permission before reserving a fresh attempt, so the permission dialog does not consume its practice time. Granting access automatically enables listening after the interviewer reads the first question; recognition pauses during playback to avoid transcribing the interviewer. Denied or unsupported microphone access leaves typed answering available. Existing resumed attempts keep their original authoritative timing. Manual microphone off stays off, and leaving or hiding the page cancels pending activation.

Questions proceed in order. There are no previous/next controls, numbered question buttons or links back to earlier answers. Earlier questions and answers remain visible in one continuous transcript above the current question. The panel moves to the new question on advancement, but incoming speech never pulls someone away from older answers they are reading. After about four seconds of silence following recognised speech, the browser reads **Done? Say yes or no.** This uses no AI request. The candidate can say yes, say no, continue speaking, or use the equivalent buttons. Confirmation replies are not saved as answer content. Only a confirmed yes advances; the final yes saves and opens review. The Done answering button offers the same confirmation for typed answers. Native boundaries, local microphone activity and a transcript watchdog cover browsers that omit speech-end events. Natural browser recognition stops restart listening; a deliberate microphone stop does not. The silence timer resets on speech and stops on deliberate microphone stop, prompt playback or exit.

Four seconds is a configurable product default, not a validated medical-interview threshold. [Stivers et al. (2009)](https://pubmed.ncbi.nlm.nih.gov/19553212/) found very short transitions in ordinary conversation; that study does not establish how much thinking time a reflective interview answer needs. The visible Listening state and explicit confirmation avoid interpreting silence alone as completion. The threshold is `ANSWER_SILENCE_MS` in `_lib/station-flow.ts`.

Optional probes run automatically after confirmation only for station slugs in `FOLLOW_UP_STATIONS` in that same file. The current authored station topics are enabled. The follow-up API enforces the same list before quota claims or provider calls; browser parameters cannot enable a station. Existing planned station questions continue in sequence. Enabled stations retain the 20-word minimum, one probe per main question, a three-probe station cap, saved-answer input and provider-failure fallback.


### Conversation and touch improvements

Confirmed answers introduce the next question with a rotating set of short transition phrases. Follow-up probes use a separate set. These transitions and yes/no checks require no generative AI request. Late confirmation words are excluded from answer content. New joins request microphone access during the original button gesture, before asynchronous shutdown or network work. The app cannot force a browser to show a native prompt after a remembered permission decision.

Phone and tablet users receive a small dismissible desktop-experience banner. Touch controls and input sizes are adjusted without changing desktop column proportions. The call uses the visual viewport to keep the transcript reachable when a mobile keyboard opens. Native speech recognition and read-aloud still depend on browser support; typed answering remains available.

The review's Generate AI feedback button sits alongside Rubric PDF. Selecting it scrolls and focuses the feedback area; completed feedback then scrolls into view. Existing feedback can be reached through View AI feedback without a new generation request. Reduced-motion preferences are respected.

Browser checks on 16 September 2026 covered 1440, 1024, 768, 390 and 320 pixel widths, including transcript history, automatic pause confirmation, spoken no/yes, feedback navigation, banner dismissal and question-bank overflow. A simulated 340-pixel visual viewport covered mobile keyboard layout. Recognition, speech synthesis and microphone permission responses were substituted for repeatable checks; physical iPad/Safari audio and native permission dialogs still need device testing.
